How this review was run

Rather than a single linear pass, the review fanned out into thirteen independent dimensions — seven over the code, six over the thesis — run in parallel. Each finding was then handed to a separate adversarial verifier instructed to re-derive it from the live repository and default to refuted unless it could independently reproduce the claim. That second pass is what removed 11 plausible-but-wrong findings.

  • Code (7): models & MIL loss · data/eval & leakage · TTA modules · train/eval CLI · reproducibility & config · live pytest run · scripts hygiene
  • Thesis (6): claims↔evidence · methodology · SOTA fact-check vs primary sources · TTA narrative honesty · writing/figures · reproducibility honesty
  • Empirical checks: ran the full test suite; recomputed all ablation cells from results-index.csv; verified TENT/SAR collect exactly 1,536 LN params; confirmed compute_w and all six equations against code.
  • Primary-source checks: every cited SOTA number fetched and compared against the original paper, including all four author-flagged RE-VERIFY items.

1. A fabricated SOTA number: Light-WVAD's XD-Violence AP (77.3) is attributed to a paper that never evaluated XD-Violence

✓ RESOLVEDHIGHconfirmedThesis · SOTA
paper/main.tex:406 (Table 4) · sota_comparison_full.tex:118,197 · prose main.tex:385

The comparison table credits Light-WVAD with 77.3% XD-Violence AP. The cited work (Wang, Zhou & Guan, Neurocomputing 2024 / arXiv 2310.05330) evaluates only UCF-Crime and ShanghaiTech, and reports only AUC — it contains no XD-Violence result and no AP metric anywhere. The 84.7 UCF cell is correct; the 77.3 XD cell has no basis in the source. This is not transcription drift (like the documented 82.17→82.19 CLIP-TSA case) — it is a number a paper never reported. It is load-bearing: it appears in the camera-ready table, in both tables of the standalone thesis fragment, and in the §6 "on par with … Light-WVAD (77.3%)" prose. Notably, the manuscript's own RE-VERIFY discipline flagged six other rows but missed this one.

Primary source (arXiv 2310.05330, full text): evaluates ShanghaiTech (95.9 AUC) + UCF-Crime (84.7 AUC) only; Tables I–VI report AUC + model-size + ablations — no XD-Violence, no AP.
Fix: replace the XD cell with "—" (metric not reported) in main.tex:406 and the two fragment tables, and drop "and Light-WVAD (77.3%)" from the §6 on-par list. The on-par-with-RTFM/MGFN claim survives without it. While there, correct the bib title for the same key (it reads "A Lightweight Weakly Supervised Learning Framework…" but the real title is "A Lightweight Video Anomaly Detection Model with Weak Supervision and Adaptive Instance Selection").
✓ Resolved — commit f694611 (quick task 260622-ukd). The fabricated 77.3% XD AP was removed everywhere: main.tex Table 4 (XD cell → "—") and the §6 on-par prose, and both tables + both prose passages of sota_comparison_full.tex ("XD not evaluated"). The correct 84.7% UCF AUC is retained. The bib title (T3-4) was corrected. Verified: grep "77.3" → none; rendered PDF on-par prose now reads "RTFM (77.81%) and MGFN (79.19%)"; no 77.3 on the comparison pages.

2. The backbone-comparison figure is built from a stale single-seed CSV, but its caption claims "three-seed means"

✓ RESOLVEDHIGHconfirmedCode · Paper-figure
paper/figures/fig_backbone_comparison.pdf · main.tex:283 · scripts/generate_pub_figures.py:227-331 · results/phase10_charts/backbone_comparison_4way.csv

Figure 3's PDF was generated (mtime 2026-06-09) from a single-seed, pre-λ0 CSV that predates the 3-seed table conversion (commit 33591ac, 2026-06-10). Its bars therefore disagree with the authoritative Tables 1/2 — e.g. CSV shows XD gated SO400M = 79.7 vs Table 2's 78.7±0.9 (the XD headline backbone), and XD gated Giant 73.6 vs 76.8±2.8 — yet the caption asserts "Visual Only and Gated Fusion bars are three-seed means." The same caption also calls Late Fusion "single-seed" while Tables 1/2 now report Late Fusion with ±std over three seeds. So the figure shows single-seed values under a "3-seed" label.

CSV row: XD,Gated Fusion,SO400M_AP=0.797413 / Giant_AP=0.736067 vs Table 2: SO400M 78.7±0.9, Giant 76.8±2.8. generate_pub_figures.py:241 "# Compute error bars … (Gated Fusion only)" — Late-Fusion bars carry no error bars.
Fix: regenerate the figure from the same 3-seed source feeding Tables 1/2, then update the caption (give all three variants ±std, drop "Late Fusion is single-seed"). If regeneration is deferred, at minimum change the caption so it stops claiming 3-seed provenance over single-seed bars. The headline numbers (82.5 / 78.7) are unaffected — this is a supporting figure out of sync with the now-authoritative tables.
✓ Resolved — commit 2e6cb6b (quick task 260622-uuu). Fixed at the root cause: generate_phase10_charts.py read a single _s42 run per cell, so a new _seed_mean() now averages each cell over seeds {42,123,2024}. Regenerated the CSV and figure (targeted single-figure regen; other figures untouched). Verified: all 24 bars equal their Table 1/2 cells to ≤0.05pp; old single-seed labels 79.7 / 73.6 / 81.7 are gone, replaced by 78.7 / 76.8 / 81.4. Caption corrected ("three fusion variants … All bars are three-seed means over seeds {42,123,2024}, matching Tables 1–2 (Gated Fusion shown with ±std)"). Clean 11-page rebuild.
