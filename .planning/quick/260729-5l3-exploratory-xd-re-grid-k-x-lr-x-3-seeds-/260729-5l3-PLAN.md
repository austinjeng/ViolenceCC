# Quick Task 260729-5l3: exploratory XD SO400M k x lr re-grid

## Why

Appendix C's XD hyperparameter sweep found a ridge where `k_topk=2` and higher LR beat
the defaults — but that sweep ran under the OLD configuration (pre-SO400M features and
pre-`lam_smooth=0`). The final shipped XD headline (SigLIP SO400M cached features, gated
fusion, `lam_smooth=0.0`, `lr=1e-4`, `k_topk=3`) has never been re-gridded. This task
re-runs the ridge — `k in {1,2,3}` x `lr in {1e-4, 7e-4, 1e-3}` x seeds `{42, 123, 2024}`
= 27 runs — under the final config to see whether the historical `k=2` gain stacks or
was an artifact of the old feature/loss regime.

**This is exploratory.** The output is a report, not thesis or paper material. See
"Hard constraints" below.

## Verified mechanics (confirmed against the working tree, do not re-research)

- `scripts/run_ablations.py:52` `RunSpec(dataset, variant, seed, config, cache_variant,
  lr_override, k_topk_override)`; `run_name` (line 87) yields
  `xd_gated_fusion_so400m_lr7e4_k2_s123`. `_fmt_lr` (line 73) maps `1e-4 -> "1e4"`,
  `7e-4 -> "7e4"`, `1e-3 -> "1e3"`.
- `run_queue(specs, results_root, err_log, dry_run)` (line 740) skips runs whose
  `run_dir/.done` exists (`is_done`, line 624), prints `[dry-run] would run <name>` per
  spec when `dry_run=True`, and returns `{"succeeded": [], "skipped": [], "failed": []}`.
- `run_one` (line 639) shells `sys.executable src/train.py --config ... --seed ...
  --results-dir <root> --run-name ... [--lr X] [--k-topk K]`, then
  `src/evaluate.py --run-dir ... --split test`, then appends a row to
  **`<results_root>/results-index.csv`**. Passing a custom `results_root` is therefore the
  isolation mechanism: the tracked `results/results-index.csv` is never opened.
- `configs/gated_fusion_xd_so400m.yaml` is the final headline config: `lam_smooth: 0.0`,
  `lr: 1.0e-4`, `k_topk: 3`, features `E:/features/xd/siglip2_so400m` + `E:/features/xd/skeleton`
  (both present on disk), epochs 50, patience 10, wandb `disabled`.
- Interpreter: `C:\Anaconda\envs\vcc-main\python.exe`. `run_one` propagates `sys.executable`,
  so launching the wrapper with that interpreter is sufficient for the child processes.
- Importing `run_ablations` pulls in `src.utils.csv_logger` -> torch at module load. A dry
  run takes a few seconds to start; that is expected, not a hang.

## Hard constraints

- **NO writes to `thesis/`, `paper/`, `results/` (including `results/results-index.csv`),
  or `.knowledge/`.** `results/` is read-only reference for the baseline comparison.
- All run outputs go under `outputs/regrid_so400m_xd/` (untracked).
- The executor agent MUST NOT launch GPU work. Task 1 ends at a committed, dry-run-verified
  script. Task 2 is orchestrator-only.
- Exploratory framing discipline: the eventual report interprets the *surface shape* only,
  with the same historical-vs-final comparability caveats Appendix C carries. No
  winner-adoption language, no "new best config" claims.
