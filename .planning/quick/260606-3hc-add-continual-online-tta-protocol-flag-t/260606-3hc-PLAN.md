# Quick Task 260606-3hc: Add continual-online TTA protocol to evaluate_tta.py

## Goal

The current TTA eval resets the adaptor **per video** (episodic), and combined with
online score-before-step + T=32 chunking on UCF's short clips (median 3 snippets, 98.4%
single-chunk), adaptation almost never reaches the scored output — so TENT/SAR were
effectively inert. Add a **continual-online** protocol (TENT/SAR's native -C setup): a
single stream-level reset per corruption condition, then adapt continuously across all
test videos with **no per-video reset**, predicting online. Make it an opt-in flag so
existing (episodic) behavior, canonical results, and all current tests are unchanged.

**Code-only.** No re-run, no paper edit, no canonical-artifact change in this task.

## Tasks

### Task 1 — `src/tta/evaluate_tta.py`: `_adapt_one_video` conditional reset

In `_adapt_one_video(...)` add a `reset: bool = True` parameter (insert it before the
closing `) -> np.ndarray:` of the signature, after `T: int = 32,`), and make the reset
conditional. Replace:
```
    adaptor.reset()
    n_snippets = skel_feat.shape[0]
```
with:
```
    if reset:
        adaptor.reset()
    n_snippets = skel_feat.shape[0]
```
- `files`: src/tta/evaluate_tta.py
- `done`: episodic callers (reset defaults True) behave exactly as before.

### Task 2 — `src/tta/evaluate_tta.py`: `run_tta_evaluation` protocol threading

a) Add a `protocol: str = "episodic"` parameter to `run_tta_evaluation(...)` (default
   keeps current behavior).
b) After the adaptor is created (the `if method == "tent"/"sar"/else` block, ~line 282)
   and BEFORE the `# 4. Load test video list` / per-video loop, insert:
```
    # Continual-online protocol (TENT/SAR native -C setup): one stream-level
    # reset, then adapt continuously across the whole corruption-condition test
    # stream with no per-video reset. Episodic (default) resets per video.
    per_video_reset = protocol != "continual"
    if not per_video_reset:
        adaptor.reset()
```
c) In the per-video loop, change the scoring call
   `scores = _adapt_one_video(adaptor, skel, clip, method, device)`
   to `scores = _adapt_one_video(adaptor, skel, clip, method, device, reset=per_video_reset)`.
d) Add `"protocol": protocol,` to the eval_metrics.json payload dict (for provenance,
   next to the existing method/lr/rho/backbone fields).
- `files`: src/tta/evaluate_tta.py
- `verify`: `grep -n "protocol" src/tta/evaluate_tta.py` shows the param, the reset guard, and the payload field.

### Task 3 — CLI flag

In `parse_args`, add:
```
    ap.add_argument("--protocol", type=str, default="episodic",
                    choices=["episodic", "continual"],
                    help="episodic (per-video reset, default) or continual "
                         "(one stream-level reset, adapt across all test videos)")
```
and pass `protocol=args.protocol` into the `run_tta_evaluation(...)` call in `main()`.
- `files`: src/tta/evaluate_tta.py
- `verify`: `python src/tta/evaluate_tta.py --help` lists `--protocol {episodic,continual}`.

### Task 4 — unit test

Add to `tests/test_evaluate_tta.py` a test that `_adapt_one_video(..., reset=False)` does
NOT call `adaptor.reset()` and `reset=True` does. Use a tiny fake adaptor with a
`reset()` call-counter and `score_only`/`adapt_and_score` returning a fixed
`torch.zeros(1, n)`; feed small numpy skel/clip arrays. Assert reset-count is 0 when
reset=False and 1 when reset=True.
- `files`: tests/test_evaluate_tta.py
- `verify`: `python -m pytest tests/test_evaluate_tta.py -q` passes (run it).
