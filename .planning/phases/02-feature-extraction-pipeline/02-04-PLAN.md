    Run the complete XD-Violence extraction pipeline across all 3 splits. This is the same 3-stage pipeline validated on UCF-Crime, now applied to a larger video-based dataset. XD-Violence uses decord for video decoding instead of PNG loading.

    **Important XD-Violence path notes:**
    - Train videos: `E:\XD_Violence\train\{video_id}.mp4`
    - Test videos: `E:\XD_Violence\test\videos\{video_id}.mp4` (nested test/videos/ subfolder -- Pitfall 8)
    - Video ID = filename without `.mp4` extension

    **Execution order (sequential -- each stage depends on the previous):**

    1. **Stage 1: Skeleton extraction (vcc-skeleton):**
       ```bash
       conda run -n vcc-skeleton python scripts/extract_skeletons.py --dataset xd --split train
       conda run -n vcc-skeleton python scripts/extract_skeletons.py --dataset xd --split val
       conda run -n vcc-skeleton python scripts/extract_skeletons.py --dataset xd --split test
       ```
       Estimated time: XD-Violence has ~3954 train + 800 test videos. Video decoding is slower than PNG loading. RTMPose inference on each frame takes ~15ms on RTX 4090. For a 3-minute video at 25 FPS = 4500 frames, that is ~67 seconds per video. Total estimate: 8-20 hours for train split.

       The train split is the longest job. Consider running it as a background process and checking progress periodically. Val and test splits are subsets.

       **CRITICAL: Do NOT wait for each command to complete before starting the next.** Skeleton extraction for train must finish before CTR-GCN train can start, but val/test can proceed independently after their skeleton stage completes.

    2. **Stage 2: CTR-GCN feature extraction (vcc-ctrgcn):**
       ```bash
       conda run -n vcc-ctrgcn python scripts/extract_ctrgcn.py --dataset xd --split train
       conda run -n vcc-ctrgcn python scripts/extract_ctrgcn.py --dataset xd --split val
       conda run -n vcc-ctrgcn python scripts/extract_ctrgcn.py --dataset xd --split test
       ```
       Estimated time: CTR-GCN forward pass is faster than skeleton extraction (~1s per video including pickle loading). Total: 1-2 hours.

    3. **Stage 3: CLIP feature extraction (vcc-main):**
       ```bash
       conda run -n vcc-main python scripts/extract_clip.py --dataset xd --split train
       conda run -n vcc-main python scripts/extract_clip.py --dataset xd --split val
       conda run -n vcc-main python scripts/extract_clip.py --dataset xd --split test
       ```
       Estimated time: CLIP inference with batch_size=64. For a 3-minute video at 1 FPS = ~180 CLIP samples per video, ~3 batches. Total: 3-6 hours.

    4. **Stage 4: Alignment verification:**
       ```bash
       conda run -n vcc-main python scripts/verify_alignment.py --dataset xd --split all
       ```
       Must exit with code 0. The 4 known CRC-corrupt files should appear in errors.log but NOT in the alignment failures (they were never extracted, so they are "missing" not "misaligned").

    **Error log checks after each stage:**
    ```bash
    cat E:\skeletons\xd\errors.log 2>/dev/null | head -20
    cat E:\features\xd\skeleton\errors.log 2>/dev/null | head -20
    cat E:\features\xd\clip\errors.log 2>/dev/null | head -20
    ```
    Expected: The 4 CRC-corrupt files appear in skeleton errors.log. These same video IDs will be missing from feature files. verify_alignment.py should report them as "SKIP (missing files)" not "FAIL".

    **Post-extraction sanity checks:**
    ```bash

    "
    ```
